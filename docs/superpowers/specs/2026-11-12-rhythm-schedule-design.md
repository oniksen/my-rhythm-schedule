# Мой ритм — статический проект расписания

Дата: 2026-11-12
Статус: на проверку, ещё не одобрен к реализации

## Зачем

Сейчас всё приложение — один файл `my_rhythm_schedule_updated.html`. Это личное недельное расписание: галочки, процент дня, календарь месяца и переменное занятие, которое чередуется по неделям. Страницу нужно разложить в маленький статический проект, который открывается на Vercel и на GitHub Pages без сборки.

Править расписание должен человек, без агента и без фреймворка. Поэтому вся неделя и список переменных занятий живут в одном файле данных. Код страницы этот файл только читает.

## Цели

- Та же страница: тот же вид, те же тексты, те же действия.
- Хостинг статики с корня репозитория: и Vercel, и GitHub Pages открывают `index.html`.
- Один файл расписания, который можно править руками: дни, пункты, список переменных занятий.
- Переменное занятие само берётся из этого списка по кругу. Кнопка в интерфейсе ставит следующее занятие на выбранную неделю и запоминает выбор в браузере.
- Пятница дополнена вечерним хвостом после необязательной учёбы.
- Кнопка и слот в воскресенье смотрят на одну и ту же неделю. Сейчас в исходнике это расходится: кнопка пишет выбор по понедельнику, а заголовок воскресенья читает его по дате воскресенья и поэтому ручной выбор в списке дня не виден. Это исправляется.

## Не цели

- Аккаунты, синхронизация, сервер, база.
- Редактирование расписания из интерфейса.
- Разные шаблоны на разные календарные недели. Меняется только переменное занятие.
- Редизайн, тёмная тема, новые экраны, клики по календарю.
- Перенос галочек из старого `localStorage`. Новый адрес — другой origin, старые данные туда сами не придут.
- TypeScript, сборщик, тесты, npm.

## Антицели

- Шаг сборки, без которого страницу не открыть.
- Особые случаи пятницы и воскресенья, зашитые в код рендера.
- Id пунктов по позиции в массиве (`d0-0`). Вставка пункта не должна переклеивать старые галочки.
- Фреймворк или много файлов логики. Расписание — один файл, поведение страницы — один файл.

## Ограничения

- Язык интерфейса — русский. Кодировка файлов — UTF-8.
- Даты считаются в локальной таймзоне браузера. `toISOString` для ключей дней запрещён: он сдвигает дату.
- Времена в исходнике используют короткое тире `–` (U+2013), например `06:00–07:20`. В подписях переменного занятия — длинное тире `—` (U+2014). Не заменять на дефис.
- Исходный `my_rhythm_schedule_updated.html` не удалять и не править. Это образец. Точкой входа становится новый `index.html`.
- Git не инициализировать и remote не создавать. README только объясняет, как выложить уже существующий репозиторий.

## Подходы

Рассматривались три способа собрать проект.

1. **Обычные файлы без сборки, расписание в `js/schedule.js`.** Страница подключает его тегом `script`, не как ES-модуль. Файл можно открыть и с хостинга, и двойным щелчком: модули с `file://` часто не грузятся. В файле допустимы комментарии. Выбран.
2. **Тот же каркас, но расписание в JSON.** Строже как данные, но без комментариев, и лишняя запятая ломает всю неделю. Для правки руками хуже. Отклонён.
3. **Vite или другой сборщик.** Лишняя установка. Дешёвая модель чаще ломает сборку, чем данные. Человеку, чтобы поменять пункт, сборка не нужна. Отклонён.

Выбран первый: так решил заказчик после сравнения вариантов 1 и 2. Вариант 3 отброшен заранее, потому что противоречит правке без агента и хостингу без сборки.

## Как устроен проект

```
index.html
css/styles.css
js/schedule.js
js/app.js
README.md
.nojekyll
my_rhythm_schedule_updated.html   # не трогать
```

Других исходников нет. `package.json`, `vercel.json` и конфиг сборки не создавать: для статики из корня они не нужны. Пустой `.nojekyll` нужен, чтобы GitHub Pages не прогонял сайт через Jekyll.

`index.html` содержит ту же разметку, что исходник, без `<style>` и без большого `<script>`. В конце `body`:

```html
<script src="js/schedule.js"></script>
<script src="js/app.js"></script>
```

`css/styles.css` — содержимое исходного `<style>` без изменений, включая неиспользуемые классы переключателя. Внешний вид не улучшать и не чистить.

`js/schedule.js` только кладёт объект в `window.SCHEDULE`. Функций в нём нет.

`js/app.js` читает `window.SCHEDULE`, рисует неделю и месяц, вешает события, пишет `localStorage`. Имена функций внутри файла — на усмотрение исполнителя. Дробить `app.js` на модули нельзя.

## Файл расписания

Вверху `js/schedule.js` — короткий комментарий по-русски, дословно по смыслу такой:

- Менять расписание нужно только в этом файле.
- Новый пункт получает новый `id`. Старый `id` не переименовывать и не отдавать другому пункту: по нему лежат галочки.
- Порядок `rotation` — это порядок по неделям. Новое занятие добавлять в конец, иначе сдвинутся уже прошедшие недели.
- У занятия есть `title` (панель справа), `description` (подзаголовок панели) и `taskTitle` (текст пункта в воскресенье).
- Ровно один пункт недели помечен `rotation: true`. Его `title` не используется.

Форма объекта:

```javascript
window.SCHEDULE = {
  anchorMonday: "2020-01-06",
  rotation: [
    {
      id: "ai-engineering",
      title: "AI Engineering",
      description: "Изучение AI, LLM и инструментов",
      taskTitle: "AI Engineering — изучение и практика"
    },
    {
      id: "kmp-installer",
      title: "KMP Installer",
      description: "Разработка KMP desktop installer",
      taskTitle: "KMP Installer — изучение и практика"
    }
  ],
  days: [ /* семь дней, понедельник первым */ ]
};
```

День:

```javascript
{
  id: "mon",
  name: "Понедельник",
  markers: ["спортзал"],   // необязательно
  note: "…",               // необязательно, только у пятницы
  tasks: [
    { id: "mon-morning", time: "06:00–07:20", title: "Утро, завтрак и сборы" },
    { id: "fri-optional-study", time: "18:00–19:00", title: "…", optional: true },
    { id: "sun-extra", time: "11:00–12:00", rotation: true }
  ]
}
```

`markers` есть только у понедельника и четверга: `["спортзал"]`. `note` есть только у пятницы. `optional: true` только у пятничной учёбы. `rotation: true` только у воскресного слота 11:00–12:00.

## Поведение

### Даты

Неделя начинается в понедельник.

- `dateKey(d)` = `YYYY-MM-DD` из локальных `getFullYear` / `getMonth` / `getDate`, с ведущими нулями. Не `toISOString`.
- `mondayOf(d)` — понедельник той же локальной календарной даты. Сдвиг: `-((getDay() + 6) % 7)`.
- `addDays` создаёт новую локальную дату, не мутирует исходную и не использует миллисекунды суток.
- Разница дней: `Math.round((Date.UTC(y,m,d) - Date.UTC(y2,m2,d2)) / 86400000)`. Так переход на летнее время не даёт 6.96 дня.
- `anchorMonday` разбирается как локальная дата `new Date(year, monthIndex, day)`, не как `new Date("2020-01-06")` (это UTC и в части поясов даёт предыдущий день).

Индекс недели: разница в днях между понедельником просматриваемой недели и `anchorMonday`, делённая на 7. Для понедельников это целое. Отрицательное значение допустимо, если листают в прошлое.

Занятие по умолчанию: `rotation[((index % n) + n) % n]`. Остаток в JavaScript для отрицательных чисел отрицательный, поэтому нужен именно положительный модуль. Иначе список длиннее двух сломается на прошлых неделях.

Проверка, которую ревью сверяет по коду:

| понедельник | индекс | занятие при текущем списке |
| --- | --- | --- |
| 2020-01-06 | 0 | AI Engineering |
| 2020-01-13 | 1 | KMP Installer |
| 2020-01-20 | 0 | AI Engineering |
| 2019-12-30 | -1 | KMP Installer |

### Ручной выбор

Ключ недели — `dateKey` её понедельника, не воскресенья и не произвольного дня.

`localStorage` ключ: `myRhythmSchedule_v3`.

```javascript
{
  checks: { "2026-11-13|fri-optional-study": true },
  extras: { "2026-11-09": "kmp-installer" },
  weekOffset: 0,
  monthOffset: 0
}
```

В `extras` лежит `id` занятия, не название. Если id нет в текущем `rotation`, запись игнорируется и берётся автоматическое занятие. Старый ключ `myRhythmSchedule_v2` не читать и не мигрировать.

Галочка: ключ `` `${dateKey}|${taskId}` ``, значение `true`. Снятие галочки удаляет ключ, а не пишет `false`.

`weekOffset` и `monthOffset` пишутся при каждом нажатии стрелок. Сохранение месяца при уходе со страницы — сознательное отличие от исходника: там `monthOffset` попадал в запись только заодно с другим сохранением.

Кнопка `#switchExtra` для понедельника открытой недели:

1. Берёт текущее занятие (ручное, если id ещё есть в списке, иначе автоматическое).
2. Ставит следующее по кругу. При одном элементе списка занятие не меняется, запись всё равно можно сохранить.
3. Пишет id в `extras[mondayKey]`.
4. Перерисовывает неделю. Месяц от этого не зависит: в календаре нет названий занятий.

Панель справа и пункт `sun-extra` обязаны показать одно и то же занятие.

### Проверка файла при старте

Если `window.SCHEDULE` нет или файл не проходит проверку, в `#weekContent` пишется список ошибок обычным текстом, обработчики не вешаются, календарь не рисуется по битым данным. Страница не должна остаться пустой и не должна бросать необработанное исключение.

Проверки:

- `anchorMonday` совпадает с `YYYY-MM-DD` и эта дата — понедельник.
- `rotation` — непустой массив. У каждого элемента непустые строки `id`, `title`, `description`, `taskTitle`. `id` уникальны.
- `days` — массив из 7 элементов. У дня непустые `id` и `name`, `id` уникальны, `tasks` — непустой массив.
- У каждого пункта непустые уникальные в пределах всей недели `id` и `time`.
- Пункт либо имеет непустой `title`, либо `rotation: true`. Оба сразу можно, но `title` у rotation-пункта не показывается.
- Rotation-пункт ровно один на всю неделю.
- `optional`, если есть, только `true`.

Рабочий `schedule.js` из этого документа обязан проходить проверку.

### Неделя

`#weekLabel`: `start.toLocaleDateString("ru-RU", { day: "numeric", month: "long" })` + ` — ` + конец недели с `{ day: "numeric", month: "long", year: "numeric" }`.

День: имя, затем дата `{ day: "numeric", month: "long" }`. Если есть `markers`, дописать ` · ` + markers через ` · `. Для понедельника это ` · спортзал`, как раньше.

Процент дня: `Math.round(done / tasks.length * 100)`. В знаменателе все пункты, включая необязательный. Необязательный не вычитается. Ноль пунктов проверка файла не пропускает.

Если у дня есть `note`, перед пунктами выводится блок `.day-empty` с этим текстом. Сейчас это только пятница.

Пункт — `label.task`. Отмеченный получает `.done`. Необязательный получает `.optional` и `<span class="optional-tag">НЕОБЯЗАТЕЛЬНО</span>`. Чекбокс с `data-key` равным ключу галочки. Время в `.task-time`, название в `.task-title`.

Название rotation-пункта — `taskTitle` выбранного занятия, не склейка строки в коде.

Смена галочки сразу пишет storage и перерисовывает неделю и месяц.

### Месяц

Стрелки меняют `monthOffset` от текущего локального месяца и сохраняют state.

Шапка календаря: Пн Вт Ср Чт Пт Сб Вс в `.cal-label`. Пустые клетки до первого дня — `.cal-day.empty`. Первый день месяца сдвигается на `(getDay() + 6) % 7`.

Клетка дня: число и, если отмечен хотя бы один пункт, процент, иначе `·`. Класс `.has-data`, если отмечен хотя бы один пункт. Класс `.today`, если `dateKey` клетки равен `dateKey(new Date())`. Клетка не кликабельна. Новых действий у календаря нет.

Статистика считается только по дням, где отмечен хотя бы один пункт. Снятие последней галочки убирает день из статистики.

- `#avgPct` — среднее процентов таких дней, округлённое `Math.round`, либо `—`.
- `#trackedDays` — сколько таких дней.
- `#completedCount` — сумма отмеченных пунктов, не число дней.
- `#bestDay` — максимальный процент дня с символом `%`, либо `—`. Это процент, не дата. Так в исходнике, не «исправлять».

`#rating`, дословно:

- нет отмеченных дней: `Отмечай пункты расписания, чтобы увидеть оценку регулярности.`
- среднее ≥ 85: `Очень хорошее соблюдение расписания. Сохраняй темп, не увеличивая нагрузку автоматически.`
- среднее ≥ 65: `Хороший результат. Большая часть плана выполняется; оставляй место для восстановления.`
- среднее ≥ 40: `Нестабильный, но полезный прогресс. Посмотри, какие блоки чаще всего оказываются слишком сложными.`
- иначе: `План выполняется нерегулярно. Это повод упростить расписание, а не компенсировать пропуски дополнительной нагрузкой.`

### Тексты, которые не в файле расписания

Их копировать из исходника в `index.html` без перефразирования.

- title: `Мой ритм — расписание`
- eyebrow: `Личный план развития`
- h1: `Мой ритм`

- заметка в шапке: `Главный фокус сейчас` / `Android Skills Tree: Junior → Middle. После освоения базы — курс Modern Android Developer.`
- заголовки блоков: `Недельное расписание`, `Дополнительное направление`, `Сводка за месяц`, `Принципы расписания`

- кнопки недель и месяцев сохраняют `aria-label` из исходника
- кнопка занятия сохраняет символ `↻` и `aria-label="Переключить дополнительное направление"`
- принципы: `Пн и Чт — спортзал. Пт — необязательный учебный блок на 60 минут. Суббота после проектной сессии и воскресный день оставлены преимущественно свободными. Пропущенные занятия не нужно переносить.`
- легенда: `День учитывается в статистике, если ты отметил хотя бы один пункт. Процент дня — выполненные пункты от общего количества запланированных пунктов.`
- подвал: `Данные хранятся локально в этом браузере. Для сохранения статистики открывай страницу в том же браузере и не очищай его данные сайта. Проценты отражают выполнение пунктов расписания, а не оценку твоей продуктивности.`
- подписи статистики: `Среднее выполнение`, `Дней с отметками`, `Выполнено пунктов`, `Лучший день`
- начальные значения статистики можно оставить как в исходнике: их сразу перезапишет рендер

Подсказка под кнопкой занятия не копируется дословно. Она собирается из `rotation`, чтобы новый пункт списка не требовал правки HTML:

`По кругу: ${titles.join(" → ")}. Кнопка ставит следующее занятие на выбранную неделю. Выбор хранится отдельно для каждой недели.`

Для текущего списка это: `По кругу: AI Engineering → KMP Installer. Кнопка ставит следующее занятие на выбранную неделю. Выбор хранится отдельно для каждой недели.`

`#extraTitle` и `#extraDesc` при старте можно оставить пустыми: их заполняет рендер недели. Не показывать захардкоженное имя, которое может не совпасть с открытой неделей.

## Как это реализовывать

Реализацию после одобрения этого документа ведёт оркестратор. Каждую задачу ниже он отдаёт новому sub-агенту `general` с моделью `opencode-go/beam-free`. Вариант модели не задавать. В промпт входит полный путь к этому документу, номер задачи, список файлов, которые задаче можно менять, и запрет менять остальные файлы и этот документ.

После каждой задачи оркестратор сам, не модель-исполнитель, сверяет главный узел со списком ниже. Если узел не сошёлся, один починивающий запуск той же модели с конкретным расхождением. К следующей задаче не переходить, пока узел не сошёлся. Исполнителю нельзя предлагать другой каркас.

### Задача 1. Оболочка и стили

Файлы: `index.html`, `css/styles.css`, `.nojekyll`.

Ревью: те же id, что в исходнике (`weekLabel`, `prevWeek`, `nextWeek`, `weekContent`, `extraTitle`, `extraDesc`, `switchExtra`, `prevMonth`, `nextMonth`, `monthName`, `calendar`, `avgPct`, `trackedDays`, `completedCount`, `bestDay`, `rating`); тексты из раздела выше на месте; стили вынесены без правки; скрипты подключены в порядке schedule, затем app; исходный html не изменён.

### Задача 2. Расписание

Файл: `js/schedule.js` только.

Ревью: `window.SCHEDULE`; семь дней; пятница из девяти пунктов, из них один optional и три вечерних после него; у воскресенья ровно один `rotation: true` без опоры на title; два занятия в `rotation` с id `ai-engineering` и `kmp-installer`; id уникальны; короткое тире во временах, длинное в названиях учёбы; комментарий вверху про id и конец списка; функций нет.

### Задача 3. Поведение

Файл: `js/app.js` только.

Ревью по коду, без переписывания удачных кусков:

- четыре примера индекса недели из таблицы выше получаются этим кодом;
- ключ ручного выбора — понедельник;
- кнопка и `sun-extra` читают один источник;
- отрицательный индекс не даёт отрицательный остаток;
- неизвестный id в storage игнорируется;
- галочка удаляется, а не становится `false`;
- необязательный пункт входит в процент;
- `#bestDay` — процент;
- битый или отсутствующий SCHEDULE показывает текст в `#weekContent` и не падает;
- рабочий файл из задачи 2 проверку проходит;
- календарь не получает кликов;
- строки оценки и формат дат совпадают с документом.

## Решения, принятые при записи дизайна

Их не переспрашивали отдельно. Они зафиксированы здесь, чтобы исполнитель их не менял.

- Классические `script`, не ES-модули.
- Ключ storage `myRhythmSchedule_v3`, без миграции v2.
- В storage пишется id занятия, не название.
- `taskTitle` лежит в данных, код названия не склеивает.
- `monthOffset` сохраняется при листании месяца.
- Подсказка под кнопкой собирается из списка занятий.
- Необязательный пункт входит в процент дня, как в исходнике.
- «Лучший день» по-прежнему показывает процент, не дату.
- Исходный html остаётся на месте.
- Git в рамках реализации не инициализировать.
